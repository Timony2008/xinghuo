# 架构概览

外层 Python supervisor 负责平台状态、最多三题并发、绝对截止时间、提交回执、题目轮转和受控恢复。模型不能代替程序确认平台完成，也不能私自增加题目或改变部署配置。

每个 Veria 题目运行时拥有单写者 SQLite Room、固定成员名单、会话、事件、证据、收件箱和有序 bump 队列。solver 的技术通知先发 coordinator；coordinator 决定广播。reporter 旁路处理固定事件截点，发布版本化报告，不阻塞解题或候选提交。

reviewer 先在自己的工作目录中复现全部已知 flag 路径，再检查遗漏和新机会，阶段证据持续保存。复核有总截止时间；题目轮转可以提前终止并保留部分结论。影响共享服务或一次性机会的重放先由 coordinator 协调。

证据完整保存在文件中。read_evidence/search_evidence 使用 Unicode 偏移、SHA-256 和路径约束提供分页与搜索；摘要或命中片段不是完整证据。正确 flag 回执触发异步获取材料归档，立即提交流程不等待文件快照。历史快照始终不是新复现证明。

本地 Veria 通过共享 Docker 工具容器执行；hosted 直接使用平台外层容器，不依赖嵌套 Docker。hosted 团队共享 kernel、网络和资源限制，私有成员目录不代表强安全隔离。

`flash4` 使用 15 分钟无新增正确 flag 的硬轮转；`no_flag_timeout=0` 使用原有主观审核和相邻两轮确认。计时、在途提交对账和关闭动作由 Python 执行，提示词只解释实际规则。
